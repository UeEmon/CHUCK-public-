# 拠点間メッシュのREL予測

2〜8か所の拠点がそれぞれ送信・受信する構成について、全拠点間のRELを
TX（行）×RX（列）のマトリックスで表示します。同じ組でも方向ごとにVOACAPを実行するため、
N拠点ではN×(N−1)経路（8拠点で56経路）を計算します。中継網の設計ツールではありません。

## 操作

1. 右側の「送受信地点」で「メッシュ（全拠点間を両方向で計算）」を選びます。TXとRXのカードが「拠点1〜N」に変わります。
2. 拠点ごとに地点プリセット、送信アンテナプリセット、受信アンテナプリセット、送信電力、雑音を設定します。受信アンテナは既定で「送信と同じ」で、送信と受信で別のアンテナを使う拠点だけ選びます。拠点別の送信電力欄はメッシュのときだけ表示され、単一RX・ダイバーシティーでは従来どおり共通の送信電力を使います。「＋ 拠点を追加」で最大8拠点です。
3. 年月・SSN・周波数・要求SNR・目標RELは「予察条件・宇宙天気」の共通値を使います。
4. 「24時間の伝搬を計算」で「メッシュ結果」タブに移ります。
5. 計算履歴から再表示でき、メッシュの選択と拠点別の電力・送受信アンテナも復元します。CSV/JSONで出力できます。

## 時間軸の表し方

| 操作 | 表示 |
|---|---|
| UTCスライダー | マトリックス全体をその時刻に切り替えます。「▶ 再生」で1時間ずつ自動で進めます |
| 周波数 | 指定した周波数のRELを表示します。「最良周波数」ではREL最大（同値ならSNR最大）の周波数のRELを示し、セル下段にその周波数（MHz）を出します |
| セルを選ぶ | 下の「経路の詳細」にその経路の周波数×24時間のRELを表示します。詳細のセルを選ぶと、その時刻と周波数でマトリックスを表示し直します |
| 逆方向を表示 | 選んだ経路のTXとRXを入れ替えた経路を表示します |
| 中継 | 「直通のみ」「1段まで」「2段まで」（既定）から選びます。中継を許すと、直通では目標RELに届かない経路のセルに↻と中継の段数を表示し、経路の詳細に中継経路・各区間のREL・周波数を表示します |

マトリックスの点は目標REL以上、灰色は欠測です。マトリックスの下に、その時刻・周波数で
目標REL以上の経路数と、両方向とも目標REL以上の組数を表示します。

## 中継到達性の判定

直通（TX→RX）のRELが目標REL未満の経路について、他の拠点を経由する経路を探します。
同じUTCで、経路のすべての区間が目標REL以上であれば「中継で到達」とします。

- 周波数を指定した場合は全区間をその周波数で判定します。「最良周波数」では区間ごとにREL最大の周波数を使います。
- 候補が複数あるときは、中継の段数が少ない経路を優先し、同じ段数なら最も弱い区間のRELが高い経路を選びます。
- 同じ拠点を2回通る経路は使いません。
- 区間のRELを掛け合わせた通しのRELは表示しません。区間どうしの相関が分からないためです。
- マトリックスの下に、中継で到達する経路数と、中継を使っても到達できない経路数を表示します。
- 中継は画面上の後処理なので、エンジンの追加実行はなく、公開版の回数制限にも影響しません。

## 方向で値が変わる理由

VOACAPの入力は送信側のアンテナ・送信電力と、受信側のアンテナ・受信雑音で非対称です。拠点が送受信で別のアンテナを使う場合も、方向によって使うアンテナが変わります。
拠点Aの電力が大きくBが小さい場合や、受信雑音が拠点ごとに異なる場合、A→BとB→AのRELは一致しません。
そのため上三角だけを計算して転記することはしません。

## 限界

- RELは各経路・UTC・周波数の月間統計で、瞬時の通信可否ではありません。
- 中継は各区間が目標REL以上かどうかだけで判定します。中継局での蓄積・転送の遅延、中継局の送受信切替、同時送信による干渉、チャネル割当、経路間の相関はモデル化していません。
- 結果の容量を抑えるため、経路ごとの生出力・入力カードは保存しません。必要な経路は単一RXで再計算してください。
- 計算は逐次実行で、8拠点では56回エンジンを実行します。公開版では1回の計算で回数制限の8回分を消費します。
- 移動局の位置は計算開始時点の値で固定します。公開版では移動局の位置連動は使えません。
