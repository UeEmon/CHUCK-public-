# 公開データの取得用コンテナと連携方式

追加日: 2026-10-31　更新日: 2026-11-05（公開データの取得・保存・読み込みを取得用コンテナに集約）

CHUCKが使う公開データ（NOAA SWPCの平滑SSN・障害レベル・Kp指数・D-RAP、NICTの電離圏観測、任意有効化のGIRO）は、取得用コンテナ（`public-data`、`app/public_data_server.py`・`app/public_data_store.py`）が扱います。提供元からの取得、ファイルへの保存、ファイルからの読み込み、連携ファイルやNOAAファイルの取り込みはすべて取得用コンテナが行い、CHUCK本体は取得用コンテナのAPIからデータを受け取るだけです。CHUCK本体は提供元へ接続せず、公開データのファイルも保存・読み込みしません（受け取ったデータはメモリーに一時的に持つだけです）。

| 構成 | 動かし方 | 取得用コンテナの設定 | CHUCKとの連携 |
|---|---|---|---|
| 公開環境（既定） | CHUCKと取得用コンテナを公開環境（インターネットに接続できる環境）で動かす。取得用コンテナが提供元から取得する | `HF_PUBLIC_DATA_SOURCE=internet`（既定） | API連携 |
| オンプレミス | CHUCKと取得用コンテナをオンプレミス（インターネットに接続できない環境）で動かす。取得用コンテナは提供元へ接続せず、公開環境の取得用コンテナが書き出した連携ファイルを読み込む（ファイル連携） | `HF_PUBLIC_DATA_SOURCE=file` | API連携 |

連携ファイル・NOAAファイルの取り込みと連携ファイルのダウンロードは取得用コンテナの管理画面だけで行います（2026-11-05から。CHUCKの管理画面からは外しました）。CHUCKとの接続状況は、CHUCKの画面の「外部データの取得時刻」に表示されます。以前のCHUCK側の設定 `HF_PUBLIC_DATA_MODE=file` は、取得用コンテナの `HF_PUBLIC_DATA_SOURCE=file` として引き続き有効です（`HF_PUBLIC_DATA_SOURCE` を設定したときはそちらが優先）。

## 取得用コンテナ

- 取得先は固定の一覧だけです（NOAAの3系列とKp指数の観測値・予報、D-RAP、NICT、管理画面で有効にしたときGIRO 3局）。CHUCKは種類名（`observed`・`predicted`・`scales`・`kp`・`kp-forecast`・`drap`・`nict`・`GU513` など）だけを指定し、URLは指定できません。
- 1分ごとに、更新間隔（NOAAの月間系列6時間、Kpの観測値10分、Kpの予報1時間、ほかは5分）を過ぎたデータを提供元から取得します。CHUCKの画面の利用者が提供元へ取得し直させることはできません（API連携の `GET /api/data/<種類>?refresh=1` は取得用コンテナ側に残していますが、CHUCKは送りません）。
- 取得した内容はCHUCKと同じ解析処理で検証し、通ったものだけを `<種類>.raw`（提供元の応答そのもの）と `<種類>.json`（取得時刻、URL、SHA-256、入手経路 `origin`：download＝提供元から取得、bundle＝連携ファイル、upload＝NOAAファイル）として `/data` に保存します。失敗しても前回のファイルを残し、60秒は再試行しません。
- 更新があるたびに、全データをまとめた連携ファイル `/data/export/chuck-public-data.json` を書き出します。
- API（いずれも `Authorization: Bearer <HF_PUBLIC_DATA_TOKEN>` が必要。ブラウザからの直接アクセスは拒否）
  - `GET /api/data/<種類>`：提供元の応答そのもの。`X-Fetched-At` に取得時刻（UNIX秒）、`X-Origin` に入手経路（download／bundle／upload）
  - `GET /api/export`：連携ファイル
  - `GET /api/status`：各データの取得時刻、GIROの設定（`giro_enabled`）、データの取得元（`source`：internet／file）、最後にファイルを取り込んだ時刻（`imported_at`）
  - `POST /api/import`（`Content-Type: application/json`、16 MB以下）：連携ファイルまたはNOAA SWPCのJSONファイル。定期ジョブなどからの取り込み用です（管理画面の取り込みと同じ処理）。検証して保存し、連携ファイルは手元より新しいデータだけを置き換えます。不正なファイルは400
  - `GET /api/health`：死活確認（認証なし）

## 管理画面

取得用コンテナの管理画面は `http://localhost:18084/` です。公開環境のサーバーでは、ポートを直接公開せず、リバースプロキシ（Caddy）の `https://data.<ドメイン>/` から開きます（サーバー構成側で管理画面のファイルと `/ui/*` だけを中継し、Bearer API `/api/*` は中継しません。画面のファイルを増やしたときは、その許可リストにも加えてください）。SSHのポート転送でサーバー自身の18084番に接続することもできます。`.env` に16文字以上の専用パスワード `HF_PUBLIC_DATA_UI_PASSWORD`（`HF_PUBLIC_DATA_TOKEN` とは別の値）を設定し、`docker compose up -d public-data` で反映してからログインします。未設定のときはログインできません。HTTPSの後ろで使う場合は `HF_PUBLIC_DATA_UI_SECURE_COOKIE=1` も設定します。

- 取得状態：データごとの提供元、更新間隔、最終取得成功時刻、入手経路（提供元から取得／連携ファイル／NOAAファイル）、直近の失敗。「今すぐ取得」で更新間隔にかかわらず全データを取得します（オンプレミスでは表示しません）。
- 連携ファイルのダウンロード（ファイル連携用）。
- 連携ファイルの取り込み：連携ファイル（chuck-public-data.json）またはNOAA SWPCのJSONファイルを取り込み、このコンテナに保存します（複数選択可）。
- GIRO · 海外電離圏観測の有効化・無効化：有効にするには、利用条件（[Rules of the Road](https://giro.uml.edu/didbase/RulesOfTheRoad.html)）への適合の確認が必要です。設定は `/data/settings.json` に保存され、再起動後も保持されます。`HF_GIRO_ENABLED=1` は、管理画面で一度も設定していないときの初期値です。
- CHUCKは取得用コンテナのGIRO設定に従います（API連携では `GET /api/status` を30秒に1回まで確認、ファイル連携では取り込んだ連携ファイルの設定）。CHUCK側でGIROを有効にする設定はありません。

ログインセッションは1時間で、HttpOnly・SameSite=Strictのクッキーを使います。8回失敗すると15分ログインできません。

## 宇宙天気デイブリーフィング（検証版）

取得用コンテナは、保存した公開データから宇宙天気のデイリーブリーフィング動画（英語表記、英日の音声、8言語の字幕）を作れます。生成AI（Gemini・OpenAI・Claude・ローカルLLM）は管理画面で工程ごとに選びます。公開・配信の機能はなく、定時の自動作成も既定で無効です。詳しくは[SPACE_WEATHER_BRIEFING.md](SPACE_WEATHER_BRIEFING.md)を参照してください。このため取得用コンテナのイメージは、ffmpegを加えた専用の段（`hf-public-data:local`）になりました。

## 公開環境（取得用コンテナが提供元から取得）

`Start.sh`・`Start.ps1` は初回起動時に `.env` へ `HF_PUBLIC_DATA_TOKEN`（48文字のランダム値）を作り、CHUCKと取得用コンテナの両方に渡します。手動で起動する場合は `.env` に32文字以上の値を設定してから `docker compose up -d --build` を実行してください。位置ゲートウェイのトークンとは別の値にします。

CHUCKは計算や表示のたびに取得用コンテナへ問い合わせ、取得用コンテナが提供元から取得した時刻を「最終取得成功」として表示します。予測条件・宇宙天気タブの「外部データの取得時刻」には、取得用コンテナに接続できているかと、オンプレミスでは最後に連携ファイルを取り込んだ時刻を表示します。取得用コンテナに接続できないときは、CHUCKが起動してから受け取った前回の値を古いデータとして表示し、60秒は再試行しません（CHUCKを再起動した直後に取得用コンテナに接続できないときは、データなしとして表示します）。

## オンプレミス（ファイル連携：取得用コンテナが連携ファイルを読み込む）

1. 公開環境で取得用コンテナを動かします（CHUCK本体は不要）。
   ```sh
   docker compose up -d --build public-data
   ```
2. 連携ファイルを取り出します。次のいずれかです。
   - `docker compose cp public-data:/data/export/chuck-public-data.json .`
   - `curl -H "Authorization: Bearer $HF_PUBLIC_DATA_TOKEN" http://127.0.0.1:18084/api/export -o chuck-public-data.json`
   - 公開環境の取得用コンテナの管理画面の「連携ファイルをダウンロード」
3. ファイルをオンプレミス環境へ持ち込み、オンプレミスの取得用コンテナの管理画面（`http://localhost:18084/`）の「連携ファイルの取り込み」で取り込みます。CHUCKの管理画面では取り込みません。

オンプレミスでは `.env` に `HF_PUBLIC_DATA_SOURCE=file` を設定し、CHUCKと取得用コンテナの両方を起動します（`docker compose up -d --build`）。この設定の取得用コンテナは提供元へ一切接続せず、定期取得・「今すぐ取得」・`--once` も行いません。

- 取り込んだデータはオンプレミスの取得用コンテナの `/data` に保存され、再起動後も使えます。種類ごとにSHA-256と内容を検証し、手元のデータより新しいものだけを置き換えます。壊れた・未知の種類は取り込まず、画面に表示します。
- 計算に必要なのは主にNOAAの平滑SSNです。予測平滑SSNは毎月更新されるため、月に1回程度取り込んでください。取り込んだデータは、より新しいファイルを取り込むまで計算に使います。
- NICT・D-RAP・GIROは現在の観測値のため、持ち込んだ時点で古いデータとして表示され、実効SSNには使えません。
- 連携ファイルに含まれるGIROの設定は、オンプレミスの取得用コンテナの設定として引き継ぎます。
- 2026-11-05より前にCHUCK本体の `/data/public-data`・`/data/space-weather`・`/data/observations` へ取り込んだデータは使われなくなります。更新後に連携ファイルを一度取り込み直してください（古いフォルダーは削除してかまいません）。
- 公開環境に取得用コンテナを用意できない場合は、NOAAのJSONファイルをそのまま取り込むこともできます（[SPACE_WEATHER.md](SPACE_WEATHER.md)の「オンプレミス運用」）。

## 制約

- 取得元（internet／file）の切り替えは取得用コンテナの環境変数で行い、管理画面からは変更できません。
- 取得用コンテナはデータをCHUCKへ渡すだけで、第三者に公開しません。各データの利用条件・出典は本体と同じです（[DATA_LICENSES.md](../DATA_LICENSES.md)）。
