# CHUCK

**C**overage & **H**F **U**sability **C**alculation **K**it

日本語 | [English](README.en.md) | [Français](README.fr.md) | [Español](README.es.md) | [Italiano](README.it.md) | [Português](README.pt.md) | [Deutsch](README.de.md) | [한국어](README.ko.md)

この日本語版は詳細版です。他言語版には導入・主要操作・制約・ライセンスの案内を掲載しています。リンク先の詳細文書は原文の言語を保持します。

CHUCK（Coverage & HF Usability Calculation Kit）は公開VOACAP計算エンジンを利用する、8言語対応のHF電波伝搬予測Webアプリです。
元のMarineサイトの画面・JavaScript・サーバー処理は使用していません。

開発者向けの構成・検証状況・残課題・再開手順は[開発引き継ぎ書](docs/HANDOVER.md)を参照してください。

## 起動

Docker Desktop（Windows/Mac）またはDocker Engine＋Compose v2（Linux）を準備します。
リポジトリを取得し、ターミナルで次を実行してください。

```sh
git clone https://github.com/UeEmon/CHUCK-public-.git
cd CHUCK-public-
docker compose up -d --build
```

ブラウザで **http://localhost:18082** を開きます。
Mac/Linuxは `sh Start.sh`、Windows PowerShellは `./Start.ps1` でも起動できます。
初回ビルドではベースイメージ・コンパイラー取得にインターネット接続が必要です。
計算エンジンのソースと地図データは同梱しており、ビルド後の計算・地図表示は外部サイトに接続しません。

停止・ログ確認：

```sh
docker compose down
docker compose logs --tail=100 -f
```

履歴はDockerの名前付きボリューム `hf-data` に保存され、通常の停止・再構築で保持されます。
`docker compose down -v` は履歴を削除するので、必要な結果は先にJSONで保存してください。

## 搭載機能

- 左側のオフライン地図、右側のTX 1局・RX 1〜8局。各RXとTXを個別に相互交換
- 地図のドラッグ移動、ホイール／サムホイール拡縮、短経路の大圏表示（クリックで局位置は変更しない）
- 地点・アンテナのプリセット専用編集画面、SQLite保存、北米・東アジア・ヨーロッパの主要都市を初期登録
- 対象年月、平滑黒点数、送信電力、アンテナモデル、利得補正、雑音、要求SNR・信頼度、最低打上げ角
- 2〜30 MHzから最大11周波数を指定（0.001 MHz単位、内部座標は0.01°単位）
- CCIR / Method 30による24時間の地点間予測、信頼度ヒートマップ、時刻別詳細
- 要求信頼度を満たす候補から信頼度・SNR順に推奨周波数を表示
- 指定時刻・周波数の地域カバー範囲（7×5の最大35地点、補間なし）
- SQLite計算履歴、履歴再読込、CSV・JSON・VOACAP入力カード・生出力
- ブラウザへの入力設定保存
- 日本語・英語・フランス語・スペイン語・イタリア語・ポルトガル語・ドイツ語・韓国語の画面切替（Language）。言語はブラウザに保存し、外部翻訳APIは使用しません
- 変調方式、要求SNRの帯域換算、TX・各RXの偏波記録と仮定した追加偏波損失
- UTC×周波数のPropagation Chart（REL/SNR・経路別MUF・RX選択・SVG保存）
- 寸法付きホイップ・水平／垂直ダイポール、米海軍・艦船・航空機用の出典付きアンテナカタログ（[モデルと制限](docs/ANTENNA_PRESETS.md)）
- 経度180°を跨いでドラッグ移動できる横方向循環地図。倍率1でも中心経度を移動可能
- 独立ゲートウェイのログイン付きWeb管理画面（[設定手順](docs/GATEWAY_WEB_UI.md)）
- カタログ・仕様書（PDF／画像）を生成AI OCRで読み取り、原本・根拠を確認してアンテナプリセットへ登録（[設定・操作](docs/ANTENNA_OCR.md)）
- OCRのOpenAI／Claude／Gemini／ローカルLLM切替、接続先モデルの取得・選択、APIキー設定と[取得手順](docs/AI_SETTINGS.md)
- 外部データの観測時刻と最終取得成功時刻を分けて一覧表示。キャッシュを待たずに最新データを個別／一括取得

国外観測データの追加候補・取得形式・利用条件は[国外電離圏データ調査](docs/INTERNATIONAL_IONOSPHERE.md)にまとめています。

## 操作

1. 右側でTX 1局とRX 1局以上の地点・アンテナをプリセットから選択します。「RXを追加」で最大8局。「TXと交換」はそのRXとTXの地点・アンテナを交換し、他のRXを維持します。
2. 地点座標の登録・編集は「地点プリセット」、アンテナモデル・利得の登録・編集は「アンテナプリセット」で行います。都市の初期座標は市中心付近の概略値で、実際の無線局の所在地ではありません。南緯・西経は負数です。
3. 「予察条件・宇宙天気」で対象年月・SSN・電力・周波数を設定します。SSNは手動またはNOAA自動取得。現在の宇宙天気・D-RAP・NICT・GIROの取得もこのタブに集約しています。「24時間の伝搬を計算」はRX 1局で地点間予察、2局以上でダイバーシティー予察を実行します。
4. ヒートマップのセルを選ぶと、そのUTC時刻の詳細と推奨周波数を表示します。
5. 「カバー範囲」タブでは、現在のRX1の位置・アンテナ・雑音で地域格子を計算します。完了後の丸の色が信頼度です。
6. 履歴タブで保存済みの条件・結果を呼び出せます。履歴一覧は最新100件、保存自体は件数無制限です。

入力を変更しても、既存の計算結果は再計算されません。結果欄の条件説明は計算時点の値です。
地図のTX/RXと短経路は現在の入力を示すので、条件変更後は再計算して比較してください。
計算結果は左の地図の下に表示し、24時間予測・ダイバーシティー結果・カバー範囲をタブで切り替えます。
地点・アンテナのカタログは履歴と同じ名前付きボリュームに保存されます（各200件まで）。
履歴・ブラウザの保存設定を読み込む際、元のプリセットが変更・削除されていれば、その計算時点の値を一時的な選択肢として復元します。
別画面との同時編集はrevisionで検出します。競合時は一覧を再読込し、対象を再び編集して保存してください。
言語切替では入力値・局ID・利用者が登録した局名／アンテナ名を変更しません。
外部提供元の原文、技術診断の詳細、ライセンス原文と配布文書は元の言語を保持します。

## 変調方式・偏波条件

「予察条件・宇宙天気」に設定を集約しています。
CW 24、SSB 45、AM 67 dB·Hzは受信品質の**例示値**として選択時に設定し、その後編集できます。
FM・FSK・PSK・QAM・OFDM等ではモデム・符号化・速度・要求BERなどに適合する必要SNRを指定してください。
方式名だけで規格適合や復号性能を保証するものではありません。
直接入力のほか、必要な帯域内SNRと受信帯域幅Bから
`SNR_1Hz = SNR_band + 10 log10(B_Hz)` として換算できます。
エンジンへ渡すのはこの1 Hz換算の要求SNRで、REL判定に反映されます。
変調波形、帯域選択性・遅延拡散に対する復号性能は計算しません。

TX・各RXにモデル依存／垂直／水平／右旋円／左旋円／その他直線偏波を記録できます。
現在の連携は同梱アンテナの利得パターンを使うため、偏波名の変更だけではパターンを切り替えず、
偏波不整合・ファラデー回転を自動算出しません。
「仮定する追加偏波損失」（全経路共通、0〜30 dB）を指定した場合だけ、
送信電力を等価的に `10^(-損失/10)` 倍して信号・SNR・RELへ反映します。
元の送信電力と追加損失は別々に条件へ保存し、利得等に含まれる損失との二重計上を避けてください。
この追加損失は利用者による感度分析であり、物理的な偏波伝搬モデルではありません。

要求SNRと方式・受信品質の関係の参考原典：
[VOACAP: Required grade of service](https://www.voacap.com/2023/understanding/rel.html)、
[Antenna patterns](https://www.voacap.com/2023/understanding/method15.html)。

## 数値の意味

- REL：要求SNR以上となる月内の時間割合に関するモデルの回線信頼度（%）。瞬時の接続成功確率とは異なります。
- SNR：VOACAPの1 Hz帯域換算SNR（dB·Hz）。受信帯域幅B HzのSNRとの比較には `SNR_B ≈ SNR_1Hz − 10 log10(B)` を使用します。
- 要求信頼度：推奨候補のしきい値、およびVOACAPの要求信頼度入力です。
- 雑音：VOACAP SYSTEMカードに渡す3 MHz基準値の絶対値。150を入力すると−150 dBWです。
- TX/RXアンテナ：基準ホイップ・等方性に加え、寸法付きモノポール・水平／垂直ダイポール。公開装備の寸法近似は実機固有パターンではありません。機体・艦体込み特性が不明なものは計算不可の参考資料です。[根拠と条件](docs/ANTENNA_PRESETS.md)を確認してください。
- 利得補正：選択モデルの利得に加える値。船体・設置・ケーブル損失等を詳細に再現するものではありません。
- 推奨周波数：入力した候補の中で選択します。周波数割当・運用許可を判定する機能はありません。
- カバー範囲：最大35個の独立した地点間予測です。連続した通信可能領域の境界を推定したものではありません。

VOACAPは月間統計モデルです。瞬時の電離圏変動、磁気嵐、地形、実機設置条件を完全には反映しません。

## ポート変更・LAN接続

既定では起動端末のみから接続できます。公開Web向けの認証機能はありません。
別ポートを使用する場合は、プロジェクト直下の `.env` に以下を記載します。

```dotenv
HF_PORT=18084
```

信頼するLANの別端末から利用する場合は、同じファイルに `HF_BIND=0.0.0.0` を追加し、
`docker compose up -d` 後に `http://起動端末のLAN-IP:18082` を開きます（上記のポート変更も行った場合は18084）。
18083はゲートウェイの既定ポートです。本体と同じポートを指定しないでください。

## 開発構成

```text
app/engine.py       固定長カード生成、検証、エンジン実行、出力解析
app/server.py       HTTP API、SQLite保存、CSV・JSON出力
app/static/         8言語対応画面、SVG地図、ヒートマップ

Dockerfile          Linux上でエンジンをビルドしPythonサーバーと実行
compose.yaml        ポート、永続ボリューム、一時ファイル領域
```

Python 3.12の標準ライブラリだけでサーバーを実装しています。JSも外部依存なしです。
各エンジン呼出しは短い一時ディレクトリに専用のrun/database/antennasを持ちます。
同時計算は1件に制限し、実行中の別要求にはHTTP 409を返します。
元の計算モデルを改変せず、入力の整形と出力解析をアダプターで行います。

API仕様は [docs/API.md](docs/API.md)、検証結果は [docs/VALIDATION.md](docs/VALIDATION.md) を参照してください。

## 宇宙天気API連携

NOAA SWPCの公開JSONをサーバー経由で取得します。APIキーは不要です。
「宇宙天気 → 取得・表示」で対象月のSSN・F10.7と現在のR/S/Gを確認できます。
「SSN取得方法 → NOAA」を選ぶと、地点間／カバー範囲の計算時に対象月の平滑SSNを取得します。
手動入力は従来どおりオフラインで利用できます。

- 月別SSN: 対象月と完全一致する観測平滑値を優先し、なければ予測平滑値を使用。日別値や近隣月では代用しません。
- F10.7（sfu）、R（電波障害）、S（太陽放射線嵐）、G（地磁気嵐）は参考表示です。VOACAPへの追加補正は行いません。
- 月別データは6時間、現在指標は5分キャッシュし、永続ボリュームに保存します。通信失敗時は古い値と明示して表示します。
  自動計算では期限切れSSNを使わず503を返します。手動モードへ切替可能です。
- R/S/Gは観測時刻が1時間より古い場合も古い値と表示。レベル不明を0（平穏）に置き換えません。
- 計算履歴とJSON・CSV出力に実際に使用したSSNの出典、対象月、取得日時、予測／観測の区別を保存します。
- NOAAの公表SSNを無変換で入力します。現行SSN尺度と旧VOACAP係数の校正、Marineサイトとの数値一致は未検証です。
- コンテナから `services.swpc.noaa.gov:443` へのHTTPS通信が必要です。位置・回線条件は外部へ送信しません。

データ仕様、比較候補、制約は [docs/SPACE_WEATHER.md](docs/SPACE_WEATHER.md) を参照してください。

## 現在の電離圏観測と吸収情報

「観測・障害情報」タブから、D-RAPとNICT国内4局の数値を取得できます。
回線マップの「D-RAP吸収」で格子を重ね、NICTの参考伝搬距離を切り替えてLUF／MUFを確認してください。
VOACAP回線MUFは別条件の参考値として併記します。観測時刻・欠測・更新遅延も表示します。

海外観測はGIROのJR055（ドイツ）、MHJ45（米国）、GU513（グアム）を選択できます。
GIROの利用条件（教育・非商用研究、共有規則等）に適合する環境、または必要な許諾を得た環境で、`.env` に以下を記載して起動してください。

```dotenv
HF_GIRO_ENABLED=1
```

```sh
docker compose up -d --build
```

無効時は海外への接続を行いません。各局の稼働状況によっては欠測します。
観測値は予測結果の自動補正には使いません。詳細・出典・利用条件は [SPACE_WEATHER.md](docs/SPACE_WEATHER.md) を参照してください。

## 移動局の外部位置入力

船舶・航空機・車両の位置を独立したゲートウェイサーバ（既定18083）で取り込み、有効な受信局を地点プリセットに自動登録します。TX/RXは右側のプリセット選択から連動できます。
登録済み移動局の名称編集を維持し、削除した自動登録局は自動で再登録しません。一覧の「登録・編集」で手動復元できます。上限到達時は不要なプリセットを削除してください。
「移動局・外部入力」で**局ごとにJSON・GeoJSON・NMEA 0183（RMC）を選択**します。
RXサイトダイバーシティーにも連動可能。期限切れを拒否し、計算に採用した位置・時刻を保存します。
外部受信用 `HF_POSITION_INGEST_TOKEN` と本体連携用 `HF_POSITION_GATEWAY_TOKEN` に、それぞれ別の32文字以上の秘密値を設定します。
`docker compose up -d --build` で本体・ゲートウェイを起動します。旧本体への位置POSTは410となるため送信先を変更してください。
接続手順・単位・サンプルは [POSITION_INTERFACE.md](docs/POSITION_INTERFACE.md) を参照してください。
本体18082・ゲートウェイ18083・内部API8001は別ポートです。ゲートウェイのhealthy表示は認証成功を保証しません。[接続確認と障害の切り分け](docs/POSITION_INTERFACE.md#接続確認と障害の切り分け)に従って本体側の位置一覧まで確認してください。
本体との連接は[HTTP(S) + 共通JSON v1](docs/GATEWAY_PROTOCOL.md)に統一し、外部形式の変換はゲートウェイが担当します。
位置は要求時点で固定し、移動経路や航空機高度による伝搬補正は計算しません。

## 複数RXサイトのダイバーシティー予測機能

右側でRXを2〜8局選択すると、自動的に単一TXから各RXへの24時間・周波数別予測を計算します。「ダイバーシティー結果」タブで比較できます。
RXごとのアンテナプリセット・雑音を設定し、最良サイト、サイト別REL/SNR、目標RELを満たすサイト数を表示。
各経路の地図表示・履歴・CSV/JSON保存に対応します。
統合確率は相関不明の理論範囲として示し、独立仮定の参考値は任意指定に限定しています。
波形合成・実受信切替・実測可用性の保証ではありません。[操作と算定方法](docs/RX_DIVERSITY.md)を参照してください。
